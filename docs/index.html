My fork of CLAI

I wanted more say in when my agents run.

I liked how CLAI lets me give a team of agents its own workspace. Once I started setting up recurring work, I got really zoomed in on the schedule. I wanted to pick the hours it could run, check whether there was anything to do, and give each workspace a way to get ready and clean up afterward. That’s how CLAI+ started.

Explore the fork ↗

What I added

One example is a workspace that checks for a new file. I can have it check during weekday hours and start the agent only once there’s a file to work on.

Pick when it can run

I can use an interval as short as 15 seconds or use cron for set times. The weekly grid lets me pick the quarter-hours when a workspace can run. That’s where I can give one workspace a morning block and give another the rest of the workday.

Give each workspace its own timing

A due workspace can make its own scheduling check while another is busy. I can pause a schedule or ask the main agent to run now. Automatic enhanced schedules use the macOS wake monitor. The app needs to be running, and the regular scheduler is available on other platforms.

Check first. Then do the work.

I can use a condition script to check whether that file exists before spending a model call. If there’s work to do, a Before script can set things up. An After script can clean up once the run is over.

I can test each script in settings and review the exact script before I let it run unattended. If cleanup gets interrupted, I can see what’s pending and decide what to do with it.

What I’m trying in my own build

These additions are still outside the public branch. I’m showing the Scheduling view with sample workspaces and runs.

See what’s running and what’s waiting

Once I had several workspaces on schedules, I wanted one place to see the queue. I added that view along with a limit on how many scheduled runs can work at once and a waiting limit for each workspace.

I’ve also worked on tray controls, Todoist settings inside a workspace, and a Google file worker with notes tied to the part of a file I’m reviewing.

I built CLAI+ on CLAI. Thanks to the CLAI contributors for the app I get to build on.
